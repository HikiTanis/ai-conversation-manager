# 软件内更新（2.1.0）

默认在启动时后台读取本仓库 GitHub Releases 的最新正式版。没有更新或网络暂时不可用时不弹窗打断工作。右上角“检查更新”可随时检查；更新窗口可关闭“启动时自动检查更新”。设置保存在应用本地首选项中。

发现新版后显示版本与发布说明。点击“立即更新并重启”后才开始下载，下载窗口显示进度。正在删除、导入、恢复或备份时不能安装更新；更新期间不能执行新的会话写入操作。

## 安装版

识别程序目录中的 `uninstall.exe`，下载同版本 Windows x64 安装包。核对 SHA-256 和大小后，独立助手等待主进程退出，以 `/S /UPDATE /R /D=<当前目录>` 调用 NSIS 安装器，保留安装位置并在成功后重启。安装失败时显示错误和缓存安装包位置，用户可以重新运行安装包。

## 便携版

下载完整 Portable ZIP，检查包内路径、必需文件及大小。助手等主进程退出后，在程序目录内准备暂存文件，逐项替换主程序、`engine/`、启动脚本和随包说明文件。只替换程序拥有的目录和文件，旁边的用户文件不会被删除；Codex/DSH 数据目录不参与更新。

旧程序文件保存在程序目录的 `.update-backup-<进程号>` 下。替换失败会尝试逐项回滚并重新打开旧程序；若有文件被其他进程占用且回滚也失败，会显示备份位置。确认新版正常后，可以手动移走旧程序备份。

## 更新来源与失败处理

- 只读取 `HikiTanis/ai-conversation-manager` 的正式发布，不接受测试版或降级。
- 下载入口固定为该仓库的对应版本资源；HTTPS 重定向只允许 GitHub 官方资源域名。
- 优先读取正式发布附件 `update.json`；不可用时回退到 GitHub API，再回退到公开发布页与 `SHA256SUMS.txt`，以兼容旧版本发布和 API 限流。
- 以发布清单、GitHub API 或校验和附件提供的 SHA-256 及对应文件大小核对下载内容。此校验依赖 GitHub/HTTPS 信任链，不等于 Authenticode 或独立离线签名。
- API 请求超时、限流、断网、包未上传齐全、无写入权限、校验失败都会停止更新。主程序在下载、校验及助手准备成功前保持运行。
- 下载与助手日志保存在应用本地数据目录的 `updates/` 子目录；助手失败时会显示 `error.txt` 所在位置。

2.0.3 及更早版本没有更新模块，需要手动升级一次到 2.1.0；此后可通过应用内更新。

## 验证

`npm test` 覆盖启动检查、提示延迟、用户确认、关闭自动检查、离线失败、重试和写入操作互斥。

`cargo test --manifest-path desktop/src-tauri/Cargo.toml --locked` 覆盖版本比较、资源来源、哈希、压缩路径、暂存篡改及便携版回滚；联网读取发布元数据的测试默认忽略，可用 `live_release_metadata_is_compatible -- --ignored` 或 `live_public_fallback_works_without_api -- --ignored` 单独执行。

`desktop/tests/updater-smoke.ps1` 使用隔离目录与合成程序演练助手等待旧进程退出、便携版替换和重启，并以模拟安装器验证安装版参数。它不安装软件到用户系统。正式构建脚本默认执行此测试。
