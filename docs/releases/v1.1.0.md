# v1.1.0 — Codex + DeepSeek Harness

## 中文

一个程序管理两种数据源，沿用原版界面，右上方直接切换 **Codex / DSH**。

### 新增

- 项目、主对话、子代理、消息预览、回收站和备份导入随数据源切换。
- 两边均支持“全部／未归档／已归档”分类；DSH 支持批量归档及取消归档。
- DSH session v4 JSONL／多帧 Zstandard 读取、关联子代理删除、整批恢复、永久清除和中断恢复。
- DSH `.dshchat` 仅对话包、`.dshproject` 项目包；导入前检查、项目目录映射、同源合并、独立复制及会话写入回滚。
- 记住上次数据源；切换清空勾选、搜索与待导入路径，写入／检查期间禁止切换。
- 保留 Codex 原有备份格式、导入、官方删除协议及侧边栏修复。Codex 归档状态可筛选，归档变更仍在 Codex 客户端操作。

### 整理与验证

- 共用界面留在 `src/CodexConversationManager`，适配位于 `Providers` 和 `adapters/dsh`，新增测试集中于 `tests`。
- 移除独立样机对主构建的依赖；更新中英文 README、格式／隐私／发布文档和 CI。
- 发布包包含界面主题、图标及 DSH 后端。Node.js 由本机提供，未打包进 ZIP。
- 合成数据覆盖 DSH 存储写入／回滚、中英文数据源切换、归档筛选、预览和备份；原 Codex 功能自测继续保留。

### 环境与边界

- Windows 10/11 x64、.NET Framework 4.8。
- Codex 删除与侧边栏修复需要 Codex CLI 0.148.0 或更高版本；查看、备份、导入不需要 CLI。
- DSH 需要支持 Zstandard 的 Node.js 22.15+ 或 24+；兼容依据为 Desktop 0.2.0-rc.2、workspace v2、session v4。
- 两种备份包不能互相导入。Codex `.jsonl.zst` 仍仅显示索引信息。
- DSH 日志读取／解压各限制 128 MiB，预览最多 200 万字符；共享附件、模型日志和插件存储不随会话清除。
- DSH 真实会话写入、客户端重启与续聊尚未端到端验证。写入前退出对应客户端，保留独立备份。
- 项目文件先还原、会话导入后失败时，已还原项目文件不保证完整自动撤销。

下载 `CodexConversationManager-Windows-v1.1.0.zip` 与 `SHA256SUMS.txt`，验证 SHA-256 后完整解压，双击 `Start.cmd`。程序未进行 Authenticode 签名；请勿混用旧版文件。

## English

One application now manages **Codex and DeepSeek Harness (DSH)** through the original UI. Use the top-right provider switch.

### Added and preserved

- Provider-specific projects, main/subagent conversations, previews, trash and backup/import.
- All / Active / Archived filters for both providers; DSH archive/unarchive actions.
- DSH v4 JSONL and concatenated Zstandard frame reading, descendant deletion, batch recovery, permanent purge and interrupted-operation recovery.
- `.dshchat` and `.dshproject` packages with inspection, destination mapping, lineage merge, independent copy and conversation-write rollback.
- Remembered provider choice, cleared selection/import state on switching, and a busy-state switch guard.
- Existing Codex formats, native import, official deletion protocol and stale-sidebar repair remain. Codex archive changes still use the Codex client.

### Organization and validation

Shared WPF UI and the existing Codex engine remain in `src/CodexConversationManager`; provider adapters live in `Providers` and `adapters/dsh`, with new regressions under `tests`. The standalone prototype is excluded. Bilingual documentation, CI and portable packaging now cover both providers. The ZIP includes the theme, icon and DSH backend scripts, but no Node.js runtime.

Synthetic tests cover DSH storage/rollback, bilingual provider switching, archive filters, preview and packages; original Codex functional tests remain in place.

### Requirements and limitations

Windows 10/11 x64 and .NET Framework 4.8 are required. Codex deletion/sidebar repair requires **Codex CLI 0.148.0 or later**. DSH requires Node.js 22.15+ or 24+ with Zstandard support and targets Desktop 0.2.0-rc.2, workspace v2/session v4.

Packages cannot be cross-imported. Codex `.jsonl.zst` stays metadata-only. DSH log input/decoded output is capped at 128 MiB and previews at 2 million characters. Shared attachments, model logs and plugin data are retained. Real DSH writes, restart and resumption have not been validated end to end. Exit the selected client before writes and retain independent backups. Restored project files are not fully rolled back if a later conversation import fails.

Download the Windows ZIP and `SHA256SUMS.txt`, verify SHA-256, extract all files together and run `Start.cmd`. The executable is not Authenticode-signed.
